# EarTimer · 技术方案

## 1. 总体架构

```
┌──────────────────────────── 主 App ────────────────────────────┐
│                                                                 │
│  AudioRouteObserver ──通知──▶ SessionEngine ──写──▶ SwiftData    │
│  （AVAudioSession 唯一真值）  （唯一写入者）        SessionRecord │
│         │                        │                    DeviceProfile
│         │                        ├──▶ LiveActivityController    │
│         │                        ├──▶ ReminderScheduler         │
│         │                        └──▶ SharedDefaults(状态快照)   │
│         │                                                       │
│  StatsStore（只读聚合）◀── SwiftData                             │
│  HomeView / HistoryView / InsightsView / SettingsView           │
└─────────────────────────────────────────────────────────────────┘
                    │ App Group (group.com.yg.eartimer)
     ┌──────────────┴───────────────┐
     ▼                              ▼
 Widget Extension            App Intents（快捷指令）
 EarTimerWidget              Start / Stop / TodayTotal
 EarLiveActivity
```

**一条铁律**：只有 `SessionEngine` 写 `SessionRecord`。视图永远不写，`StatsStore` 永远不写。
所有「重连、通道切换、被杀、心跳断裂」的时序问题都收口在一个类里，改 bug 只改一个地方。

## 2. 连接检测：三层准确度

### Tier 1 · 快捷指令蓝牙自动化（最准）

用户一次性配置：`快捷指令 → 自动化 → 蓝牙 → 选耳机 → 连接时 → 运行「开始记录耳机时长」`。

```swift
struct StartTrackingIntent: AppIntent { ... }   // 写入 pendingShortcutStart
struct StopTrackingIntent: AppIntent { ... }    // 写入 pendingShortcutStop
```

- 触发时 App **不必在运行**，`UserDefaults`（App Group）里落一个时间戳
- App 下次启动 / 回到前台时，`SessionEngine.reconcile` 消费这个时间戳，生成一条 `source == .shortcut` 的记录
- 误差：**亚秒级**（就是自动化本身的调度延迟）

这是唯一能做到「戴上耳机就记、摘下就停」的路径，务必在引导里教。

### Tier 2 · 路由监听（App 活着时）

```swift
AVAudioSession.routeChangeNotification
```

- 只关心 `outputs` 里的 `bluetoothA2DP` / `bluetoothHFP` / `bluetoothLE`
- 忽略 `.categoryChange` / `.override`（那是 App 自己切 category 导致的抖动）
- 需先 `setCategory(.playback, mode: .default, options: [.mixWithOthers])` + `setActive(true)`，
  否则冷启动首次读到的路由可能还停在扬声器

**设备身份**用 `名称(小写) + 通道族` 而不是 UID —— 蓝牙 UID 每次重连都会变：

```swift
var key: String { "\(channel.isWireless ? "bt" : "wired")://\(name.lowercased())" }
```

### Tier 3 · 心跳推算（兜底）

App 每次确认「耳机还连着」时写 `et.pending.heartbeat = now`。
若下次启动发现有一条 `endedAt == nil` 的历史记录，但当前没有耳机：

```
cut = clamp(lastHeartbeat, startedAt, now)
record.endedAt = cut
record.isEstimated = true        // UI 打「推算」徽章
```

误差可达数分钟，所以**必须**打标。

## 3. 计时模型

不用 `Timer`。用 `TimelineView(.periodic(from:by:1))`：

```swift
TimelineView(.periodic(from: .now, by: 1)) { context in
    Text(DurationText.clock(context.date.timeIntervalSince(startedAt)))
}
```

好处：页面切走自动停、进后台自动停、不持有时钟引用、预览里能注入时间。

## 4. 数据模型

```swift
@Model final class SessionRecord {
    var id: UUID              // 稳定主键（Intents / Live Activity 互相引用）
    var deviceKey: String     // 规范化设备 key
    var deviceName: String    // 断开时快照，之后改名不影响历史
    var startedAt: Date
    var endedAt: Date?        // nil = 进行中
    var channelRaw: String    // music / call / lowEnergy / wired / other
    var sourceRaw: String     // live / routeChange / shortcut / inferred / manual
    var hadCall: Bool         // 会话中是否发生过通话
    var isEstimated: Bool
    var note: String?
    var averageVolume: Double
}

@Model final class DeviceProfile {
    var key: String           // unique
    var name: String
    var accentIndex: Int      // UI 点缀色
    var dailyBudgetSeconds: Int
}
```

**跨天切分**：`overlap(with: DateInterval)` 精确处理跨零点的会话，统计永远按本地自然日。

## 5. 已知限制（写进 App 的「关于」页，别藏）

| 限制 | 原因 | 缓解 |
|---|---|---|
| App 被杀后无法感知连接 | iOS 不开放蓝牙状态 API | 快捷指令自动化 |
| 连接 ≠ 佩戴 | 摘下一只仍保持连接 | UI 文案统一写「连接时长」，不写「佩戴」 |
| Live Activity 上限 8 小时 | 系统限制 | 超时自动关闭，记录照常 |
| 小组件不刷新秒 | WidgetKit 15 分钟粒度 | 用 `Text(timerInterval:)` 让数字自走 |
| 路由名可被用户改名 | 系统只给 `portName` | 用 key 归一 + 允许改名 |

## 6. 性能

- SwiftData 查询全部带 `fetchLimit`，历史列表 `prefix(200)`
- `StatsStore.refresh()` 只在前台 / 状态变化时调用，不在 `body` 里算
- 热力图 / 时段分布用一次全量 fetch 算完，不做 N 次查询
- 数字视图统一 `.monospacedDigit()`，避免每秒重排

## 7. 测试要点

| 场景 | 期望 |
|---|---|
| 耳机连上 → 播放 → 摘下 | 一条记录，`source = .live` |
| App 在后台，耳机连上再摘下 | 两条：一条 `inferred` 或由快捷指令补全 |
| 听歌中来电 | 同一会话 `hadCall = true`，`channel = .call`，不拆行 |
| 两只耳机轮换 | 两条独立记录 |
| 跨零点（23:50 → 00:20） | 昨天 10 分钟 + 今天 20 分钟 |
| 时区变化 | 按新时区的自然日重新切分 |
| 秒表对拍 | `clock()` 与系统时钟误差 < 1s |
