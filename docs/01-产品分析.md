# EarTimer · 产品分析

> 一句话：**把「耳机连上手机」这个瞬间变成一个可统计的事件，然后围绕时长做健康与习惯的解读。**

---

## 1. 先定性：这不是一个「难做的功能」，而是一个「难拿准的数据」

用户以为你要做的是「计时器」。实际你要解决的是三个数据问题：

| 问题 | 本质 | 难度 |
|---|---|---|
| 耳机什么时候连上的？ | iOS **没有**给第三方 App 开放蓝牙连接状态 API | ★★★★★ |
| 什么时候断开的？ | 同上，且 App 被杀后彻底失联 | ★★★★★ |
| 「连着」等于「在用」吗？ | 摘下一只耳机仍保持连接，连接时长 ≠ 佩戴时长 | ★★★☆☆ |

先把第一件事说透，因为它决定整个产品的形态：

**iOS 允许你观察的，只有「音频输出路由」**（`AVAudioSession.currentRoute`）。

- 耳机连上并且成为输出设备时，路由变成 `bluetoothA2DP` / `bluetoothHFP` / `bluetoothLE`
- 路由变化会发 `AVAudioSession.routeChangeNotification`
- **但这个通知只在你的 App 存活（前台 / 刚被唤起 / 正在后台播放）时才收得到**
- App 被系统挂起或杀掉之后，耳机连上你是不知道的，没有任何补发机制

所以任何一款做「耳机连接时长」的 App，本质上都在做**概率性推算**，区别只在于推算做得多聪明。这一点决定了产品的诚实度设计：**你必须把「精确 / 推算」标在界面上**，否则用户一旦发现数据不对，就再也不会打开第二次。

### 唯一能拿到 100% 准确的路径：快捷指令自动化

iOS 的「快捷指令 → 个人自动化 → 蓝牙」支持「当某耳机连接 / 断开时」触发，**触发时不要求 App 在运行**。这是系统给用户的合法能力，也是这个品类唯一能做到接近真实的地方。

所以产品架构必须是：

```
准确度分层
├── Tier 1  快捷指令蓝牙自动化   → 事件驱动，误差 < 1 秒       （引导用户配置，一次性成本）
├── Tier 2  App 存活期间监听路由  → 误差 < 1 秒               （免费，但只在用 App 时生效）
├── Tier 3  心跳 + 前台校准推算   → 误差可达数分钟            （兜底，必须打「推算」标记）
```

**产品结论：把「配置一次快捷指令」做成新手引导里最显眼的一步，而不是藏在设置里。**
它决定了这款 App 是「玩具」还是「能长期用的工具」。

## 2. 功能矩阵

### P0 · 没有它就不成立

| 功能 | 说明 | 为什么是 P0 |
|---|---|---|
| 本次连接时长 | 秒级走动，大号等宽数字 | 用户第一眼要看的东西 |
| 今日累计 / 总累计 | 今日、本周、全部 | 「总时长」是长期价值锚点 |
| 自动记录会话 | 连接即开始、断开即结束，落成一条记录 | 手动记的东西没人记 |
| 历史列表 | 按天分组，显示起止时间与时长 | 数据要能被回看才可信 |
| 数据来源标记 | 「实时 / 自动 / 快捷指令 / 推算」四种徽章 | 诚实度 = 留存率 |
| 手动修正 | 改起止时间、加备注、删记录 | 补 Tier 3 的锅 |

### P1 · 决定它是不是一个好 App

| 功能 | 说明 |
|---|---|
| **灵动岛 / 锁屏实时计时** | Live Activity。连上就上岛，用户不用开 App 就能看时长。这是这个品类最爽的一下 |
| **桌面小组件** | 小号显示本次时长（`Text(timerInterval:)` 自走，不用刷新），中号显示今日累计 |
| **连续佩戴提醒** | 60 分钟提醒休息。这是「工具」升级成「健康助手」的关键一步 |
| **每日听音预算** | 设 5 小时，环形进度条走到 100% 变色。给了用户一个「为什么每天要打开」的理由 |
| **快捷指令 App Intents** | 「开始记录 / 结束记录 / 查今天听了多久」，后者还能接进「早安播报」 |
| **按设备统计** | AirPods Pro 68% / Beats 32%。多副耳机的人会非常喜欢 |
| **时段分布** | 24 小时热力，看自己几点最爱戴。洞察页的骨架 |
| **热力图** | 近 30 天方格矩阵，连续天数 |
| **CSV 导出** | 给数据控，也是「你的数据属于你」的姿态 |

### P2 · 加分项 / 差异化

| 功能 | 说明 | 附注 |
|---|---|---|
| **听力负荷（HealthKit）** | 读 Apple 健康的 `headphoneAudioExposure`（耳机音频暴露，dB），和你的时长结合成「负荷」 | 真差异化。这是苹果自己在测的数据，但没人为你做成「今天该不该再听」 |
| **日历式月度视图** | 月历上每天涂色，一眼看整月 | 纯情绪价值，留存很高 |
| **年度报告卡片** | 年底生成一张图「今年你戴了 1264 小时耳机，最爱的时段是 21 点」 | 分享即获客 |
| **专注模式联动** | 开始「工作专注」时自动开始计时 | 用小众自动化做口碑 |
| **多设备对照** | 两副耳机同周对比 | 小众但深 |
| **家人共享只读** | 给孩子/老人设时长上限 | 商业化方向 |

### 明确不做（写进 README，避免被问）

| 想要的功能 | 为什么不做 |
|---|---|
| 显示耳机左右耳电量 | 苹果不开放。第三方拿不到 AirPods 电量，只能靠私有 BLE 广播嗅探，随系统版本失效且审核风险高 |
| 精确「佩戴时长」（摘下即停） | 需要区分「连接」与「在耳」。只能靠音频播放状态近似（`AVAudioSession.isOtherAudioPlaying` / `MPNowPlayingInfo` 播放态），精度不可靠，会误导用户。**改成在 UI 上说清楚「这是连接时长」** |
| 耳机固件 / 型号识别 | 系统只给 `portName` 字符串，不给型号 |
| 后台常驻监听 | 靠播静音维持后台属于滥用 `audio` 后台模式，审核会拒，且耗电 |

## 3. 竞品与差异

| 类型 | 代表 | 它们的做法 | 你的机会 |
|---|---|---|---|
| 电量类 | AirBattery / Battery HD | 蓝牙扫描 + 私有广播 | 它们不做时长，做不了精细统计 |
| 屏幕使用时间类 | 系统自带 Screen Time | 只统计 App，不统计耳机 | 完全空白 |
| 计时类 | 各式番茄钟 | 手动开始 | 手动 = 没人用 |
| 健康类 | Apple 健康 | 有音频暴露数据，但不做「会话」 | 你可以把「会话」做成它的前置 |

**差异化定位建议（二选一，别都做）：**

- **A · 极简仪表盘**：一个环 + 两个数字，别的什么都没有。卖「安静」。
- **B · 耳朵健康助手**：时长 + 音量暴露 + 休息提醒 + 周报。卖「为你好」。

当前实现走的是 **A 的皮 + B 的骨**：视觉极简，功能上把健康闭环做全（预算、提醒、负荷）。

## 4. 关键用户路径

```
首次打开
  ├─ 授权通知（为一小时后提醒休息）
  ├─ 引导页三屏：① 它是干什么的 ② 为什么不装快捷指令会不准 ③ 一键跳转快捷指令配置
  └─ 空状态：环形灰环 + 「戴上耳机，这里会开始走」

日常
  戴上耳机 ──→ 灵动岛上岛（Tier 1/2 命中时）
            └─ 60 分钟后本地通知「摘下歇 5 分钟」
  摘下耳机 ──→ 记录落库，历史页当天多一行
  想看看    ──→ 小组件 / 锁屏，不用开 App

每周
  洞察页 ──→ 本周柱状图、时段分布、连续天数
```

## 5. 数据诚实度设计（最重要的一条产品原则）

任何一处推算的时间，UI 上必须同时出现：

1. 列表行尾的 **「推算」** 徽章（琥珀色）
2. 详情页的一句解释：**「这条时长是推算的（App 当时不在运行）」**
3. 允许用户手动改，改完自动降级为「手动」来源

反向约束也一样：**不要为了让数字好看而四舍五入**。宁可显示 `0:47`，也不要显示「约 1 小时」。

## 6. 审核与合规要点

| 项 | 做法 |
|---|---|
| 后台模式 | **不开** `audio` 后台。只在 `Info.plist` 里声明 Live Activity |
| 隐私清单 | `PrivacyInfo.xcprivacy`：不追踪、不收集、无 Required Reason API 滥用 |
| 健康数据 | 若启用 HealthKit，`NSHealthShareUsageDescription` 必须写清楚「只读取耳机音频暴露，不上传」 |
| 权限申请时机 | 通知在用户看到第一个环形计时之后再申请，通过率显著更高 |
| App 名称 | 「EarTimer」比「AirPods 时长」安全，避免商标问题 |

## 7. 商业化（如果你要上架）

| 模式 | 具体 |
|---|---|
| 免费 | 今日 + 本周统计、单个设备、Live Activity |
| 订阅 ¥18/年 | 全部历史、无限设备、CSV 导出、年度报告、听力负荷 |
| 一次性 ¥28 | 买断（更符合小工具气质，转化通常更好） |

定价的关键不是功能多少，而是**「我已经记了 3 个月，不能丢」**——历史数据本身就是付费墙。
